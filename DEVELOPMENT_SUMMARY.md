# Development summary

I built this classroom survey app for CSE 4095 by giving Cursor the five specification files and asking it to follow them one phase at a time. I did not want it to invent a different stack. The spec already chose React, TypeScript, Vite, Tailwind, Supabase, PostgreSQL, Recharts, the `qrcode` package, GitHub, and Cloudflare. My job was to read what it produced, run the checks, and stop it when a box in `TODO.md` was not actually tested.

The first prompt was only a reading pass. Cursor explained the two users, the five tables, and the things the spec leaves open, and then waited. I approved Phase 1 next. The project folder already held the Markdown files, so the Vite app was created beside them instead of replacing them. That pass added the landing page, the route list, the Supabase client, and `.env.example`. It did not add a database or a working login.

Phase 2 was the part I had to apply myself. Cursor wrote `supabase/migrations/20261106020000_initial_schema.sql` and a 22-check script. I pasted the migration into the Supabase SQL Editor and ran the checks there. All 22 passed. Those checks switch roles inside the SQL Editor and then roll back, so I did not treat them as proof that the website’s anonymous key was safe. I ran a separate script with that key. It could see only the active survey, it could submit once, a second submit with the same token returned `DUPLICATE_RESPONSE`, and reading `responses` returned permission code `42501`. An instructor sign-in could read draft, active, and closed surveys, read one response, and update a draft. Creating and deleting a survey were not in that script, so that TODO line is still open.

The React side talks to Supabase directly. There is no server of my own. `src/lib/supabase.ts` reads `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`. Instructors sign in with `signInWithPassword`. The session is restored with `getSession` and `onAuthStateChange`, and instructor routes redirect to `/login` when there is no session. Students never sign in. They open `/s/:slug`, and the page calls `get_public_survey_status` and then reads the active survey. A submit goes through `submit_survey_response`, which checks that the survey is active, that every question is answered, and that the choice belongs to that question. The browser keeps an anonymous token in `localStorage`. The same token cannot be stored twice for one survey because of the unique index. I kept the service-role key out of the frontend. Any signed-in user is treated as the instructor, so public sign-up stays off.

Cursor then generated the dashboard, editor, presentation page, student page, results page, and CSV export in one request for Phases 3 through 13. I told it not to add the Phase 16 extras. The editor saves drafts, including multiple-choice and true/false questions. True and false are two choice rows. Activation uses the existing `activate_survey` function, which closes the other active survey and keeps the public slug. If a survey already has responses, a later edit changes the title and description and leaves the questions in place, so old answers are not deleted. Results compute a count and a one-decimal percentage, and the CSV quotes every cell and prefixes formula-like cells with an apostrophe.

A few problems were real, not theoretical. The Vite template wanted TypeScript 7 and Oxlint, but the ESLint packages I needed only accept TypeScript below 6.1, so the project uses TypeScript 6.0.3 and ESLint. Prettier could not parse `.env.example`, so that filename is ignored. Docker was not available here, which is why the migration was applied in the Supabase website instead of locally. My first instructor test used `read -p` in zsh, which does not set the variables, and Supabase answered “missing email or phone.” The zsh prompt form fixed it. ESLint also rejected two `useEffect` hooks that set state immediately. Those were rewritten so the state update happens after the request. The production JavaScript file is larger than Vite’s 500 kB notice. The build still finishes.

I pushed the repository to GitHub and deployed it as a Cloudflare Worker at https://classroom-survey.eshisrivastava93.workers.dev. The spec says Cloudflare Pages. The hostname that is actually live is `workers.dev`, and the repo has no `wrangler.toml`. Deep links such as `/login` and `/s/notarealslug` return the app shell, so the single-page fallback is working. I signed in on that site.

What I would do differently is test the student path before calling the MVP done. I have not yet created a survey on the live site, scanned its QR code, submitted from a phone, confirmed the duplicate message, or opened the CSV in a spreadsheet. The code for those screens is in the project. The boxes stay unchecked until I do those clicks.
